## 2026-10-26 — cache: a failed read is no longer a fresh read

- **Defect:** the retry-exhaustion branch stamped data.time = now, cleared .incomplete and cleared .retryPending. On a FIRST inspect that never resolved this left an EMPTY record that isCacheFresh then reported as fresh for the full 300 s window: no GearScore line and no re-inspect for five minutes. hands-up.md already documented the intended rule (do not stamp cache time); the retry path obeyed it, the exhaustion branch did not.
- **Fix (LibForeverInspector):** exhaustion leaves .time alone, keeps .incomplete = true, clears .retryPending, and sets failedUntil = GetTime() + 20 (CACHE_FAILED_BACKOFF). isCacheFresh treats that window as "may skip an inspect", so the next hover does not hammer NotifyInspect, and after 20 s the entry is askable again. A fresh inspection or a complete commit clears failedUntil.
- **Also fixed:** eviction refused incomplete entries outright, so failed records could never be reclaimed and the 512 ceiling could be defeated. Eviction now ages them by lastAttempt (written on every cache write) and still never removes an entry whose retry is in flight.
- **Pins:** exhaustion keeps the last complete stamp (not a new one) and keeps .incomplete; failedUntil parks the entry and expires on the test clock; a failed FIRST inspect has no .time and serves GetLastCacheTime 0; the ceiling holds when 512 failed records accumulate; a retrying entry survives eviction. One existing pin ("exhaustion leaves a terminal, non-incomplete state") was rewritten on purpose: it encoded the defect.
