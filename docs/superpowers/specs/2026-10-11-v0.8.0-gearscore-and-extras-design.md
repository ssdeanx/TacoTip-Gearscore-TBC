This specification defines the architectural enhancements and defect resolutions required for the release of **TacoTip_Forever v0.8.0** and the standalone companion addon **TacoTip_Extras v1.0.0**.

The primary objectives are:

   - Eliminate improper 50% score dampening on standalone two-handed weapons (Ret Paladins, Arms Warriors, Casters with staves, Feral Druids, Hunters).
   - Accurately isolate the `TitanGrip = 0.5` dampening factor strictly to active dual-wield scenarios where an off-hand item is equipped alongside a 2-handed weapon (WotLK/Titanforge Fury Warriors).
   - Ensure `ITEM_BAND_SCALE` correctly maps per-item GearScore values to their visual rarity bands across all supported game clients.
   - Synchronize Hunter weapon scaling between character total calculations (`GetScore`) and tooltip item evaluation (`GetItemHunterScore`).

## 2. Technical Problem Analysis & Solutions

### 2.1 The Two-Handed Weapon & Titan's Grip Defect

#### Problem
In `gearscore.lua:485-490`, commit `5deecbc` replaced the guard `if (mainHandLink and offHandLink)` with `if (mainHandLink)`. Under the mistaken premise that a 2-handed weapon "occupies both slots 16 and 17 in the API and offHandLink is always nil," the code set `TitanGrip = 0.5` whenever any 2H weapon was present in slot 16.

This halved the score of every standalone 2H weapon in the game:
- An ilvl 200 rare 2H weapon (`INVTYPE_2HWEAPON`) has a base score of `621` with `SlotMOD = 2.0`.
- Standalone 2H wielders (Retribution Paladins, Arms Warriors, Hunters, Casters with staves) received only `floor(621 * 0.5) = 310 GS` for their weapon slot.
- Meanwhile, a 1H weapon (310 GS) + Shield (310 GS) contributed `620 GS`.
- Consequently, two-handed weapon wielders were penalized by half their weapon value (~311 GS deficit at ilvl 200).

#### Root Cause & Resolution
In the World of Warcraft client and GearScore design:
- `SlotMOD` for `INVTYPE_2HWEAPON` is `2.0` precisely because it takes up both hand slots and provides equivalent item budget to two 1H items (`1.0 + 1.0 = 2.0`).
- When a player equips a standard 2H weapon, slot 16 has the item and slot 17 is empty (`offHandLink == nil`). Its full `2.0` weight is required so that the player's weapon gear contribution matches a 1H+Shield or 1H+1H wielder.
- **Titan's Grip** is a Level 60 WotLK Fury Warrior talent that permits wielding two-handed weapons in one hand.
- Only when a character has an offhand item equipped alongside a 2-handed weapon (`mainHandLink and offHandLink`) does dual-wielding 2H weapons become possible.
- **Correct Logic:**
  ```lua
  local TitanGrip = 1.0
  local offHandTitanGrip = 1.0
  if (mainHandLink and offHandLink) then
      local mhEquipLoc = select(9, GetItemInfo(mainHandLink))
      local ohEquipLoc = select(9, GetItemInfo(offHandLink))
      if (mhEquipLoc == "INVTYPE_2HWEAPON") then
          TitanGrip = 0.5
      end
      if (ohEquipLoc == "INVTYPE_2HWEAPON") then
          offHandTitanGrip = 0.5
      end
  end
  ```
  - When a solo 2H weapon is held: `offHandLink` is nil -> `TitanGrip = 1.0`. Mainhand score: `621 * 1.0 = 621`. Offhand: `0`. Total weapon score = `621`.
  - When dual 2H weapons are held (Titan's Grip): `mainHandLink and offHandLink` is true -> `TitanGrip = 0.5`, `offHandTitanGrip = 0.5`. Mainhand score: `621 * 0.5 = 310`. Offhand score: `621 * 0.5 = 310`. Total weapon score = `620`.
  - When 1H + Shield is held: `mainHandLink and offHandLink` is true -> neither is 2H -> `TitanGrip = 1.0`, `offHandTitanGrip = 1.0`. Mainhand score: `310`. Offhand score: `310`. Total weapon score = `620`.
  - Perfect mathematical balance is restored.

### 2.2 Asynchronous Item Loading & API Resilience

#### Problem
In modern clients (Retail, WoW Forever, and modern Classic flavors), `C_Item.GetItemInfo` can return `nil` if an item's data is uncached on the local client. In older routines, destructuring unpacks from a nil return could yield `nil` values into downstream arithmetic calculations, causing Lua errors. Furthermore, when duplicate items are equipped (e.g. identical rings in slots 11 and 12), asynchronous callbacks must not register duplicates or trigger redundant UI flushes.

#### Resolution
1. **Protected Item Info Fetching:**
   ```lua
   local function safeGetItemInfo(link)
       if not link then return nil end
       local fn = (_G.C_Item and _G.C_Item.GetItemInfo) or _G.GetItemInfo
       if fn then
           return fn(link)
       end
   end
   ```
2. **Safe Nil-Fallback Returns:**
   In `scoreFromItemValues` and `scoreFromItemInfo`, if item data is uncached or missing, safely return the standard zero tuple `0, 0, 0.1, 0.1, 0.1, 0` and request asynchronous caching via `C_Item.RequestLoadItemDataByID` (when available).
3. **Deduplicated Asynchronous Callbacks:**
   Maintain deduplication within `cb_table.items` so multiple slots with identical item IDs register a single pending entry, preventing premature or duplicate completions.

### 2.3 Hunter Weapon Scaling Parity

#### Problem
In Classic Era, TBC, and WotLK, Hunters utilize ranged weapons (bows, guns, crossbows) as their primary offensive gear and melee weapons as secondary stat-sticks. In GearScore architecture:
- Melee weapons (slots 16, 17) receive a `0.3164` multiplier.
- Ranged weapons (slot 18) receive a `5.3224` multiplier.

#### Resolution
Ensure exact multiplier alignment between character aggregate score (`TT_GS:GetScore`) and single-item tooltip queries (`TT_GS:GetItemHunterScore`):
```lua
if (PlayerEnglishClass == "HUNTER") then
    if (i == 16 or i == 17) then
        TempScore = TempScore * 0.3164
    elseif (i == 18) then
        TempScore = TempScore * 5.3224
    end
end
```

### 2.4 Quality Color Banding (`ITEM_BAND_SCALE`)

#### Problem
The color of an item tooltip line should accurately reflect its GearScore relative to the client's tier bracket:
- Classic Era / WoW Forever: `BRACKET_SIZE = 200`
- TBC Anniversary: `BRACKET_SIZE = 400`
- Titanforge / Retail: `BRACKET_SIZE = 1000`

`ITEM_BAND_SCALE = 11.25` rescales per-slot scores into the character total domain (which aggregates ~16-17 item slots) so that high-end gear displays Epic/Legendary coloring rather than collapsing into low-quality bands. Retain `ITEM_BAND_SCALE` and ensure `TT_GS:GetQuality(GearScore * ITEM_BAND_SCALE)` applies cleanly across all slots.

### 3.2 Direct Binding to `LibForeverInspector`
In `TacoTip_Extras/TacoTipAdapter.lua`:
- Refactor `findInspector()`:
  ```lua
  local function findInspector()
      local libStub = _G.LibStub
      if type(libStub) ~= "table" or type(libStub.GetLibrary) ~= "function" then
          return nil
      end
      -- Prioritize LibForeverInspector from TacoTip_Forever
      local ok, library = pcall(libStub.GetLibrary, libStub, "LibForeverInspector", true)
      if ok and type(library) == "table" then
          return library
      end
      -- Fallback to legacy alias if registered
      ok, library = pcall(libStub.GetLibrary, libStub, "LibClassicInspector", true)
      if ok and type(library) == "table" then
          return library
      end
      return nil
  end
  ```
