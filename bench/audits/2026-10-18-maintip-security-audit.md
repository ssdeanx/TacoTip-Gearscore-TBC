# Security audit — TacoTip main addon v0.8.4 (stage6-security)

**Verdict: no blockers, no majors. The addon is safe to ship from a security standpoint.** Every chat write is intentional and rate-limited; the 0.8.x Pawn chat-spam class has no proven live sibling; SavedVariables are sanitized with allowlist resolvers at the unsafe sinks; nothing leaves the client (no addon-message sends anywhere in the main addon); no secure/taint-sensitive frames are touched. Five minors below are hardening only.

**Placement note:** this session exposed only read/grep/glob — no file-write and no shell. Journal, signals, and this bench report are placed by the orchestrator from the lane's inline handoff. Harness evidence is by code-reading, marked accordingly.

**Deployment/trust model assumed:** single-user WoW client addon; no hostile co-tenancy; SavedVariables treated as user-hand-editable data (self-inflicted corruption is a robustness issue, not an attacker path); Pawn/LibSharedMedia treated as semi-trusted third parties; Blizzard engine APIs trusted. If the threat model instead includes malicious local SavedVariables authoring as an attack vector, m1 rises to major — nothing else changes.

## Reviewed-clean (explicitly not findings)

- **Chat writes:** `safeCall` dedups via `handlePipelineError`, once per distinct message per session, recorded in `TT.lastTooltipError` for `/tacotip diag` (`main.lua:246-266`). All `print` sites enumerated: login-once welcome (`main.lua:3694-3699`, `CAfter(3)`), user-invoked slash/diag/mover messages (`main.lua:3359-3609, 3879, 3948, 3975, 3993`; `options.lua:388-476, 645, 1854`; `gearscore` bootstrap 44-70). No per-frame or error-loop chat path exists. **[VERIFIED]**
- **Format strings:** untrusted data (names, guild, realm) is always a `%s` *argument*, never the format string; the only locale-driven format (`FORMAT_GUILD_RANK_1`) is `"%s %s"` uniformly across all 11 locales. **[VERIFIED]**
- **Privacy/exfiltration:** zero references to `SendAddonMessage` / `C_ChatInfo` / `RegisterAddonMessagePrefix` / `SendChatMessage` in `main.lua`, `options.lua`, `pawn.lua`, `gearscore.lua`, `textures.lua`, `LibForeverInspector`, `LibDetours` (dedicated per-file greps, all no-match). Only outbound traffic is the engine inspect query (`NotifyInspect` via the library — inherent to the hover-inspect feature). `GetGuildInfo` reads only the tooltip unit (`main.lua:1853-1854`). Tests/ (which contain `print`/`loadstring`) are not in the `.toc` and do not ship (`TacoTip.toc:11-32`). **[VERIFIED]**
- **Dynamic code:** no `loadstring`/`RunScript`/function-constructor in shipped files (only `Tests/harness/*`). SavedVariables are data-only, never executed. **[VERIFIED]**
- **Taint:** hook targets are `GameTooltip.FadeOut` (DetourHook, `main.lua:3679`, `options.lua:281`), `UIErrorsFrame:AddMessage` + `C_Sound.PlayVocalErrorSound` + globals `PlayVocalErrorSoundID`/`PlaySound` (Classic-Era-only, `LibForeverInspector.lua:4713-4726`). None is a protected/secure frame or function. `InCombatLockdown` respected on the delay path (`main.lua:2419`), hide-in-combat (`2002`), inspect refresh (`3239`). Dropdowns/sliders/color-picker touch only config + own frames. `guardBlizzardInspectGuildFrame` (`main.lua:3175-3187`) wraps a non-secure inspect-frame updater in `pcall`. **[VERIFIED]**

## Ranked findings (all minor — hardening sketches only)

**m1 — `custom_anchor` has no SavedVariables allowlist; corrupt value raises from a `hooksecurefunc` post-hook** (`main.lua:2916-2917`; sanitizer `options.lua:175-270` doesn't cover it; slash path constrains to 5 literals at `options.lua:441-459`, but hand-edited SV bypasses that). *Exploitability:* self-inflicted only — requires hand-editing SV; effect is a Lua error on spell/item anchor, tooltip keeps default position (hooksecurefunc post-hook errors don't break the original call). *Fix sketch:* in `SafeSanitizeConfig`, reset `custom_anchor` to `"TOPLEFT"` unless it is one of the five literals. *Validate:* set garbage in SV, `/reload`, hover a spell — no error. **[VERIFIED]**

**m2 — Pawn chat-spam sibling hinges on one unverifiable-from-repo assumption** (`pawn.lua:96-104`): guessed `"MrRobot:"/"Classic:"` names go to `PawnGetSingleValueFromItem` on the premise it "never calls `VgerCore.Fail`". That premise is asserted in comments/`README:174-175` and modeled by the harness stub, but Pawn's source is not in this repo so the real-client behavior is **[UNKNOWN]**. Blast radius is small: the in-addon `GetScore` path never passes a nil/unguessed name (proven-name gate at `pawn.lua:164-177`, Fail-capable `PawnGetScaleColor` only ever receives registry-proven names at `217-219`), so the guessed path fires only for external `TT_PAWN` consumers passing nil. Existing `PawnScaleNameContract` pin (`Tests/TacoTip_Forever_Tests.lua:609-660`) observes `GetScaleColor`/`IsVisible` but not `GetSingleValueFromItem` chat behavior. *Fix sketch:* resolve-then-call inside `GetItemScore` (return 0 on nil scaleName instead of guessing), or document the external-caller contract; add an in-game check. *Validate:* in game (see confirmations §1). **[ASSUMED-safe, needs in-game proof]**

**m3 — Untrusted display strings concatenated raw into tooltip text** (e.g. guild `main.lua:1914`, realm `:1950`, spec text `:2070`, names `:1749`). A hostile guild/character name containing markup could spoof tooltip lines/colors. No code execution is possible (no `SetHyperlink` on untrusted data anywhere; markup escapes render only). Player-name charset restrictions make this largely theoretical. *Fix sketch (optional):* strip `|` from guild/realm/spec display strings at render. **[VERIFIED-path, ASSUMED-charset — needs in-game proof that `|` is untypable]**

**m4 — Inspect suppressor `name == nil` fallback is deliberately overbroad** (`LibForeverInspector.lua:4639-1648`): any UI error with an unresolvable message-type arriving inside the 0.5 s post-probe window is swallowed (e.g. a coincidental bag-full toast), and the `probeDepth > 0` path swallows without name-matching. Never swallows while `InspectFrame` is shown or SYSMSG-shaped messages; each swallow is counted (`inspectStats.suppressed/suppressedVoice/suppressedSound`) and visible in `/tacotip diag`. Effect is transient toast loss, not a security boundary. No change recommended; recorded so a future widening beyond Classic Era re-reviews it. **[VERIFIED]**

**m5 — `TT:RefreshCharacterFrame` has no `InCombatLockdown` guard, asymmetrically with `RefreshInspectFrame`** (`main.lua:3086` vs `:3239`). Benign: it touches only own `FontString`s on non-secure `PaperDollFrame` (`SetText`/`Show`/`Hide`/plain-frame movers — all legal in combat; `PLAYER_EQUIPMENT_CHANGED` fires mid-combat). *Fix sketch (optional):* mirror the inspect early-return. *Validate:* confirmation §4. **[VERIFIED]**

## In-game-only confirmations needed

1. **Pawn silence on real clients:** with Pawn installed, hover unit + item tooltips on Retail and on a Classic-family client; chat must stay silent (closes m2). Include a class/spec with no Pawn scale to hit the nil-scale path.
2. **Corrupt-SV behavior:** garbage `custom_anchor` → single error, no cascade (m1 fix validation); garbage `tooltip_font`/textures → silent fallback via allowlist resolver (`options.lua:892-901`).
3. **Suppressor fidelity (Classic Era):** background scan near range limit produces no popup/sound, while the player's own `/inspect` refusal still displays (m4 window behavior).
4. **Combat:** character frame open in combat with unlocked movers; no `ADDON_ACTION_BLOCKED` (m5).
